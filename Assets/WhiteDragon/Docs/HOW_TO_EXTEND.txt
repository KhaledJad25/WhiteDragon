WHITEDRAGON - HOW TO EXTEND
===========================
All content lives under Assets/WhiteDragon. Data assets live in Assets/WhiteDragon/Data/Resources/<Folder>
(Items, Synergies, Effects, Statuses, Enemies, Characters). Everything is placeholder and may change.

EDITOR TOOLS (menu Tools/WhiteDragon)
- New > Item / Synergy / Shot Effect Asset / Status Effect / Apply-Status Effect / Enemy / Character:
  type a name, press Enter. The asset is created in the right folder with a unique lowercase id,
  then selected so you can fill it in. It never overwrites an existing asset.
- Content Browser: every asset by tab, with search (name, id, tags) and item filters (tag, pool, rarity).
  Click a row to select it. "New" creates one for the current tab. "Validate" checks everything.
- Validate Content: lists errors (must fix) and warnings (check) in the Console and a results window.
  Click a result to select the asset. It never changes anything.
- Run Tests: runs all tests; the summary appears in the Console.
- Item and synergy Inspectors show a one-line summary at the top and warn about empty or duplicate ids.
  Hover any field for a plain-language tooltip.
- Testing a build: on the Player in Sandbox.unity, add items to DevTestLoadout > Items, then press Play.
  (Editor and debug builds only. Empty list = no effect.) In Play, F1 opens the debug panel.


1. ADD AN ITEM (no code)
   1. Tools/WhiteDragon/New/Item, type the name, Enter.
   2. Fill description, tags (lowercase, e.g. "fire"), statModifiers, recipeEdits, effects, rarity, poolIds.
      Defaults: Common, pool "normal", weight 1, no unlock. The summary at the top shows what it does.
   3. Tools/WhiteDragon/Validate Content, fix any errors.
   4. Test: add it to DevTestLoadout on the Player and press Play (or F1 > Add in Play).

2. ADD A SYNERGY (no code)
   1. Tools/WhiteDragon/New/Synergy, type the name, Enter.
   2. Set tag (matches item tags) and requiredCount, then statModifiers / recipeEdits / effects.
   3. Validate: it warns if fewer items carry the tag than requiredCount (it could never turn on).

3. ADD A SHOT EFFECT (one small class + one asset)
   1. Create Scripts/Combat/<Name>Effect.cs. File name = class name, namespace WhiteDragon.
   2. class <Name>Effect : ShotEffect. Override only the hooks you need:
        ModifyRecipe(recipe, stacks)          before firing
        OnSpawn(shot) / OnUpdate(shot, dt)    while flying (shot.Projectile: Velocity, GravityScale,
                                              Recipe, Owner, IgnoreTarget(...))
        OnHit(shot, target, point)            after the rock damaged something
   3. Keep per-shot data in an object returned from CreateState() (read it via shot.State), never in
      fields. Scale strength by shot.Stacks. Randomness: RunSession.Rng with RandomStream.Combat.
   4. Add [Tooltip] to its fields. Do NOT edit Projectile.cs. Copy SplitOnHitEffect.cs as a template.
   5. Tools/WhiteDragon/New/Shot Effect Asset, pick the new type, name it, Enter.
   6. Drag the asset into an item's or synergy's effects list.

4. ADD A STATUS EFFECT (no code)
   1. Tools/WhiteDragon/New/Status Effect, name it, fill duration, tickInterval, damagePerSecond,
      speedMultiplier, tint, stacking, maxStacks.
   2. Tools/WhiteDragon/New/Apply-Status Effect, pick the status, Enter.
   3. Drag that effect into an item or synergy. F1 in Play has a button to apply it to the nearest enemy.

5. ADD A POOL (no code)
   1. Type the new pool name (lowercase) into poolIds on the items that belong to it.
   2. Set an ItemPedestal's pool field to the same name.
   3. Validate warns if a pedestal's pool has no item that can appear (it would fall back to "normal").

6. ADD A STAT (one enum line, maybe one default)
   1. Append one line at the END of StatType (Scripts/Core/StatType.cs). Never reorder.
   2. If its starting value is not 0, add a case in StatBlock.DefaultBase.
   3. Read it where it matters: GetComponent<PlayerStats>().Stats.Get(StatType.YourStat).
   4. Items, synergies and characters can use it immediately; F1 shows it automatically.

7. ADD AN ENEMY
   1. Tools/WhiteDragon/New/Enemy, name it, fill maxHealth, moveSpeed, contactDamage, tint.
   2. In the scene: empty GameObject + CharacterController (height, radius, center at half height)
      + Enemy (StatusReceiver is added for you). Assign the definition.
   3. Add primitive children for the look and REMOVE their colliders (chunky, exaggerated shapes).
   4. Drag it into a RoomController's enemies list.
   5. A new BEHAVIOR (ranged, charging...) needs code: a new MonoBehaviour implementing IDamageable,
      driven by an EnemyDefinition, using Enemy.cs as the template.

8. ADD A DAMAGE TYPE
   1. Append one line at the END of DamageType (Scripts/Combat/DamageType.cs).
   2. Add its rock tint in DamageTypeColors.Tint (otherwise it shows the Physical color).
   3. Use it from an item or synergy: recipeEdits > overrideDamageType + damageType.

9. ADD A RARITY
   1. Append one line at the END of ItemRarity (Scripts/Items/ItemRarity.cs).
   2. Add its base weight at the end of BaseRarityWeights in ItemPoolRoller.cs (otherwise weight 1).
   3. Add its orb color in ItemPedestal.RarityColor (otherwise grey).

10. ADD A CHARACTER (no code)
   1. Tools/WhiteDragon/New/Character, name it, Enter.
   2. Fill statOverrides (only stats that differ from the defaults), startingItems,
      startingRedContainers, startingSoulHearts / startingDarkHearts (half hearts), description.
   3. Select the Player in Sandbox.unity and drag the asset into CharacterApplier > Character. Play.
   4. Empty Character field = default stats, 3 hearts, no items. "rock_thrower" reproduces the defaults.
   5. Never let unlocks raise baseline stats; unlocks only widen what CAN appear.


RULES THAT KEEP CONTENT EASY TO CHANGE
- Enums (StatType, DamageType, ItemRarity, RandomStream): append only, never reorder.
- Never rename, remove or reorder serialized fields. Add new fields at the end.
- Gameplay randomness: RunSession.Rng.<Method>(RandomStream.X, ...). Cosmetic only: UnityEngine.Random.
- Unlock progress is hidden: never show locked items, counts or unlock text to the player.
- Static state must reset in a [RuntimeInitializeOnLoadMethod(SubsystemRegistration)] method.
- Editor/debug-only behavior: use a runtime check (Application.isEditor || Debug.isDebugBuild),
  never the DEVELOPMENT_BUILD or UNITY_64 symbols.
- One main type per file; file name = class name; namespace WhiteDragon.
- Tools/WhiteDragon/Create Starter Content recreates missing starter assets and never overwrites.
- Run Validate Content and Run Tests before committing.
